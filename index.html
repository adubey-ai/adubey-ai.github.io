LLM Inference Benchmarking — Intel Gaudi2 vs Gaudi3 </>

vLLM Serving · Latency / Throughput / Energy · Accelerator Evaluation

Vendor-neutral inference benchmarking of dense, Mixture-of-Experts, and vision-language models across Intel Gaudi2 and Gaudi3 — serving models through the vLLM Habana fork, DeepSpeed, and Optimum Habana while logging per-token latency alongside hl-smi power traces to derive energy cost per token.

7,199 prompt-level measurements 36 device configurations 7 models · 7B → 70B 2 accelerator generations

Throughput: Gaudi3 leads across model families — +22% on Mistral-7B (109.6 → 134.0 tok/s), +38% on Llama2-7B (78.8 → 109.0 tok/s), and +27% on Llama3.1-70B multi-card (41.8 → 53.2 tok/s).

Latency: inter-token latency falls 19% on Gaudi3 (9.11 → 7.40 ms) at a steady-state ~26 ms TTFT, sustaining interactive-grade token streaming for 7B serving.

Energy trade-off: Gaudi2 delivers 1.9× better energy per token (2.27 vs 4.35 J/token on Mistral-7B) — the throughput-optimal and energy-optimal deployment are not the same hardware.

3 CNN backbones 4 Raspberry Pi nodes 10 federated rounds

High-Performance DL Software Stack for Scalable and Efficient LLMs

Jul 2025 — May 2026

M.Tech Thesis · IIST · Completed

The academic half of my Intel work: a training stack for large language models that pairs distributed execution (DeepSpeed ZeRO, FSDP, DDP) with Sliding Window Flash Attention — an attention kernel that labels every block as fully-inside, intersecting, or fully-outside the causal window, then computes only the blocks that can contribute. The thesis derives the masking, proves the numerics hold, and measures what the sparsity is actually worth.

Efficiency: 93.8% GPU utilization across multi-GPU configurations, 65% compute savings from block classification in narrow-window regimes, and a 40% energy-efficiency improvement over the dense distributed-training baseline.

Numerics: per-position masking validated to sub-microsecond agreement with dense attention across 19 test configurations — the savings come from skipped blocks, not from an approximation.

Scope note: this is the same body of work as the Intel SWFA effort — the internship shipped and productionized it, the thesis formalizes and evaluates it. The shared figures are one result reported twice, not two.

Thesis and kernel source are in private repositories — available on request.

IASW — Agentic Document Verification with a Human-in-the-Loop Boundary </>

May 2026

Multi-Agent Orchestration · Local Multimodal LLM · Banking Workflow

An agentic system that automates the manual "Maker" role in core-banking account changes while keeping the human "Checker" as the only write authority. Staff submit a legal name-change request with supporting documents; a pipeline of agents validates the request, extracts fields from the document image, scores the match, and hands a reviewable summary to a human — running entirely on a local Qwen2.5-VL-7B-Instruct with no external API calls.

4 specialized agents 7B local vision-language model 0 external API calls

Agent pipeline: Validation → Document Processor (Tesseract OCR + VLM field extraction + forgery check) → Confidence Scorer → Summary, each with typed Pydantic contracts and a full SQLite audit trail.

HITL boundary: the RPS write call is reachable from only the checker-decision endpoint, so no agent can commit a change autonomously — the constraint is enforced in code, not in a prompt.

Design call: chose a local 7B VLM over a hosted frontier API because data locality was the binding compliance requirement — sensitive documents never leave the host, and inference carries no per-token cost.
